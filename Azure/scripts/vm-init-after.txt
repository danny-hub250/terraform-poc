vm-init.sh 실행(kubectl, helm 설치) 이후 추가로 해야 할 작업
=================================================================

ACR 이름은 baxrndprdacr 입니다.

1. Azure 로그인 (아직 안 했다면)
-----------------------------------------------------------------
az login
az account set --subscription "<subscription-id>"

2. AKS kubeconfig 연결 (이미 했으면 스킵)
-----------------------------------------------------------------
az aks get-credentials --resource-group bax-rnd-prd-app-rg --name bax-rnd-prd-aks --overwrite-existing
kubectl get nodes

3. AKS <-> ACR 연동 (필수, 아직 안 함)
-----------------------------------------------------------------
이거 없으면 baxrndprdacr에서 이미지 pull 시 403 에러 납니다.

az aks update -n bax-rnd-prd-aks -g bax-rnd-prd-app-rg --attach-acr baxrndprdacr

4. (이미지를 직접 build/push 할 경우) ACR 로그인
-----------------------------------------------------------------
az acr login --name baxrndprdacr

az acr build를 쓸 거면 이 로그인은 불필요함 (서버사이드 빌드라 az login만 되어 있으면 됨).

[에러] az acr login 실행 시 DOCKER_COMMAND_ERROR / "Please verify if Docker
client is installed and running." 가 뜨는 경우
-----------------------------------------------------------------
원인: az acr login은 내부적으로 Docker 클라이언트를 호출해서 docker login을
수행하는 명령인데, jumpbox에 Docker가 설치되어 있지 않아서 발생.

[업데이트] vm-init.sh에 Docker 설치 단계를 추가함 (get.docker.com 스크립트로
설치 + azureuser를 docker 그룹에 추가). vm-init.sh를 재실행하면 해결됨.
단, 그룹 권한은 재접속해야 적용되므로 vm-init.sh 실행 후 SSH 재접속 필요.

  sudo ./vm-init.sh
  exit
  ssh azureuser@<jumpbox-ip>   # 재접속 (docker 그룹 권한 적용)

  az acr login --name baxrndprdacr
  docker build -t baxrndprdacr.azurecr.io/myapp:v1 .
  docker push baxrndprdacr.azurecr.io/myapp:v1

로컬 Docker 빌드가 필요 없는 경우에는 여전히 az acr build로 대체 가능:
  az acr build --registry baxrndprdacr --image myapp:v1 .
  (az login만 되어 있으면 됨, 로컬 Docker/az acr login 둘 다 불필요)

---
이후는 선택 사항

5. (선택) Ingress 컨트롤러 - 외부에서 앱 접근 필요할 때
-----------------------------------------------------------------
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm install ingress-nginx ingress-nginx/ingress-nginx -n ingress-nginx --create-namespace

6. (선택) 모니터링(Container Insights)
-----------------------------------------------------------------
az aks enable-addons -a monitoring -n bax-rnd-prd-aks -g bax-rnd-prd-app-rg

[참고] 새로 만든 구독(subscription)에 처음 배포할 때 겪을 수 있는 문제
-----------------------------------------------------------------
새 구독은 Azure 내부적으로 초기화가 완전히 끝나기까지 시간이 좀 걸림.
겪었던 증상 2가지:

1) terraform plan/apply가 아무 로그도 없이 멈춘 것처럼 보임
   원인: azurerm provider 4.x가 기본으로 "core" Resource Provider
   11개(Microsoft.ManagedIdentity, Microsoft.ContainerService 등)의
   구독 등록 여부를 확인하고, 미등록 상태면 등록 완료까지 순차 대기함.
   새 구독은 이게 전부 미등록이라 각각 등록 완료까지(몇 분씩) 기다리며
   멈춘 것처럼 보임.
   해결: providers.tf에 resource_provider_registrations = "none" 추가
   (완료, 이미 반영됨). 실제 필요한 provider는 az provider register로
   미리 등록해두면 됨.

2) AKS 생성 시 "AuthorizationFailed ... resourcegroups/write" 에러
   (AKS의 System-Assigned Identity가 노드 리소스그룹(MC_...) 생성 권한이
   없다는 에러)
   원인: 계정 자체는 Owner라 권한 문제가 아니라, 새 구독의 RBAC/역할
   할당 백엔드가 아직 완전히 전파되지 않아서 AKS identity에 대한
   자동 Contributor 부여가 실패함. 이 상태에서는 az role assignment
   create 자체도(누구에게 어떤 scope로 주려고 해도) MissingSubscription
   에러로 전부 실패함.
   해결: 시간 문제라 기다리는 것 외엔 방법 없음. 20~30분 정도 후
   terraform apply 재시도(이미 만들어진 리소스는 건너뛰고 AKS부터
   이어서 진행됨). 그래도 안 되면 더 기다렸다 재시도.
